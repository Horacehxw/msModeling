## 2. 核心研究结论（9 条）

### 结论 1: KV 维度 = 预分配 pool 大小（paged 场景）

vLLM PagedAttention 的 paged 路径（decode + chunked prefill）传给 FIA kernel 的 K/V tensor 是整个 KV cache pool（预分配内存池），不是按实际 seq length 切片的 tensor。真实长度通过 `actual_seq_lengths_kv`（标量列表）和 `block_table`（页表）传递。

CANN 8.3 和 8.5 行为一致，3.20 会议假设"8.5 的 KV 维度能对上"不成立。

**数据验证**：Qwen3 TP=16，不同输入长度（1024→8192），K shape 始终是 `12307-12308`（pool block 总数），完全不变。

### 结论 2: Non-paged prefill 是唯一例外，但数据极少

Non-paged prefill（PrefillNoCache 路径）的 K/V 是真实长度。触发条件：新请求首次 prefill 且不需要 chunking。CANN 8.5 数据中仅 2/24 行是 non-paged prefill。对查询设计影响小，优先级低。

### 结论 3: DSV3 prefill 不走 FIA，走 RINGMLAPrefillBF16Kernel

profiling 验证：DSV3 的纯 prefill 场景 FIA 行数为 0，只有 `RINGMLAPrefillBF16Kernel`。FIA 仅出现在 decode step。

**修复方式**：修改 MLA decomposer（`_decompose_mla`）的 prefill 分支，将 FIA SubKernelSpec 替换为 `RINGMLAPrefillBF16Kernel`。op_mapping.yaml 同步更新 `sub_kernels` 列表为 decode/prefill 并集。

**RINGMLAPrefillBF16Kernel 分析**：
- op_mapping 已有 entry（`profiling.RINGMLAPrefillBF16Kernel`），CSV 数据已有（14 行）
- 是 vllm-ascend 的自定义 kernel（ATB ring_mla_operation），融合了 ring attention + KV projection
- **和 FIA 有相同的"tensor 值控制计算量"问题**：
  - `seqlen` 参数（CPU tensor，int32，shape `[batch]` 或 `[2, batch]`）包含每个请求的实际 token 数
  - 调用链：`torch_npu.atb.npu_ring_mla(seqlen=query_lens)` → op-plugin `RingMlaAtb.cpp` → ATB `ring_mla_operation.cpp` → `RINGMLAPrefillTiling()`，tiling 用 `sum(qSeqLen)` 计算实际 workload
  - CSV 只记录 tensor shape，不记录 seqlen 值。同 shape 不同 seqlen → duration 差 3.5 倍（Row 2: 309us vs Row 3: 89us，Q shape 均为 (2048,16,128)）
  - **因此 RING kernel 也不能用标准 compute 路径匹配，需要类似 FIA 的 enriched CSV 方案**
- query_mode 应为 `"attention"` 或新增专属模式，不是 `"compute"`
- E4 microbench 需同步覆盖 RING kernel 的 seqlen 维度扫描

### 结论 4: Profiling FIA 数据不能用于查询

Raw CSV 只记录 tensor shape 不记录值。`actual_seq_lengths_kv` slot 只有 shape `(batch_size,)` 信息，不知道每个请求的真实 context length。FIA duration 是 O(query_tokens × context_length)，缺 context length 的查询结果不可信。

现有 decode 数据看似稳定（58-64us）是因为该批 profiling 的所有请求恰好有相似的 context length，不是 kernel 不敏感。

**Profiling FIA 数据的定位**：仅用于验证 E4 microbench 精度（同 workload 下对比 microbench 预测值 vs profiling 实测值），不参与查询。

### 结论 5: E4 microbench 不能取消

E4 的价值是提供 `avg_seq_len` 和 `sparse_mode` 维度数据的唯一干净来源。我们控制输入参数，直接知道 actual_seq_lengths 的值和 sparse_mode 设置。Profiling 数据天然缺这些维度。

### 结论 6: CSV 格式统一为 raw + enriched，不需要两套格式

E4 microbench 输出的 FIA CSV = raw profiling 31 slots + 新增 `avg_seq_len` 列（INT，单位 token）+ `sparse_mode` 列（INT，0-4）。查询代码只需一条路径。不需要维护"短期 raw CSV + 长期结构化 CSV"两套 schema。

**Enriched CSV 只需 2 个新增列**（基于 CANN 源码分析的 FIA 性能关键参数）：

| enriched 列 | 类型 | 说明 | 为什么需要 |
|-------------|------|------|-----------|
| `avg_seq_len` | INT | mean(actual_seq_lengths_kv)，单位 token | 决定 O(S_kv) 计算量，raw CSV 无此值 |
| `sparse_mode` | INT | 0=no_mask, 1=all_mask, 2=left_up, 3=right_down, 4=band | causal(2/3) 跳过 ~50% 计算 vs 全量(0/1)，标量参数不在 CSV |

**以下维度可从 raw CSV 推导，不需要 enriched 列**：

| 维度 | 推导方式 |
|------|---------|
| num_heads (N) | Q shape slot 0 第二维 |
| head_dim (D) | Q shape slot 0 第三维 |
| num_kv_heads | K shape 最后一维 / head_dim（paged 3D merge 场景） |
| dtype | Input Data Types 列 |
| query tokens (T) | Q shape slot 0 第一维 = sum(actual_seq_lengths)，已在 raw CSV |
| input_layout | Q ndim（3D=TND, 4D=BNSD），影响 dispatch 不影响计算量 |
| block_size | K shape 中间维度（paged 场景） |

Profiling FIA 数据的 `avg_seq_len` 列标为 unknown（或 -1），不参与查询和插值，仅做 E4 验证 ground truth。

### 结论 7: CANN 8.3 TND vs 8.5 BNSD layout 差异

同一个 MLA decode FIA，CANN 不同版本使用不同 Q layout：
- 8.3: TND `(T, 16, 512)` + rope `(T, 16, 64)` — T = total tokens
- 8.5: BNSD `(B, 16, 1, 512)` + rope `(B, 16, 1, 64)` — B = batch, S=1 (decode)
- TC dispatch 始终是 3D `(num_tokens, num_heads, qk_head_dim)`

**匹配逻辑**：归一化方向为 CSV → squeeze 到 3D。如果 CSV Q shape 是 4D 且第三维 = 1（BNSD decode），squeeze 掉 S 维度后和 TC 的 3D shape 直接比较。固定 (N, D) 精确匹配。

### 结论 8: MLA composite FIA 子内核仅需 decode 路径

已在结论 3 中覆盖。Prefill 改用 RINGMLAPrefillBF16Kernel，不再生成 FIA SubKernelSpec。

### 结论 9: `_lookup_attention()` 直接覆盖为查询 enriched CSV

不新增 `_lookup_attention_raw()` 方法，直接覆盖现有 `_lookup_attention()` 实现：
- 从 CSV Input Shapes slot 0 解析 Q shape，归一化到 3D (T, N, D)
- 从 enriched `avg_seq_len` + `sparse_mode` 列读取
- 固定 (N, D, num_kv_heads, dtype, sparse_mode) 精确匹配，avg_seq_len 精确匹配或 sqrt 插值
- 忽略 KV slots（pool 大小无语义）
- `_interpolate_attention()` 同步改为在 enriched CSV 的 avg_seq_len 上做 sqrt 插值
- `_lookup_attention_by_params()` 同步改（MLA composite 用）
- 旧的结构化 CSV 路径直接删除，不做兼容

**当前代码状态**：FIA 相关的所有 shape 转换和匹配逻辑都是新开发工作。现有 `_lookup_attention()` 只支持结构化 CSV（`batch_size, avg_seq_len, num_heads, head_dim` 列），`_inputs_match()` 只用于 compute ops。

**可复用的现有代码**：`DTYPE_MAP`、`_parse_shape_str()`、`_interpolate_from_candidates_sqrt()`、`_is_decode_mla()`。

| ZH 报告建议 | 本文档结论 | 差异原因 |

## 5. ZH 注意事项

1. **不要保留结构化 CSV 兼容路径**：直接覆盖 `_lookup_attention()`，旧的 `required_cols = {"batch_size", "avg_seq_len", ...}` 检查和 mask 逻辑全部删除
2. **Q shape 归一化方向：TC 2D → 3D 对齐 CSV**：TC attention dispatch 的 query 是 2D `(T, hidden_size)`，CSV slot 0 是 3D `(T, N, D)`。归一化方向应为 TC → 3D：从 key tensor 获取 `head_dim = key.shape[-1]`，算 `num_heads = hidden_size // head_dim`，TC shape 拆成 `(T, N, D)`。**不应该反过来 CSV 3D → 2D**，因为合并 `N*D` 会丢失 head 配置信息（不同 (N,D) 组合 duration 不同）。现有 `_lookup_attention()` 已经在做这个提取（line 1237-1246）。BNSD 4D 的 CSV 行则 squeeze S=1 维度后变成 3D `(B, N, D)` 统一处理
3. **MLA decomposer 的 prefill 分支**：RINGMLAPrefillBF16Kernel 和 FIA 有相同的"tensor 值控制计算量"问题。`seqlen` 参数（CPU tensor）包含 per-request 实际 token 数，CSV 不记录该值。同 Q shape (2048,16,128) 下 duration 差 3.5 倍（309us vs 89us）。因此 **RING kernel 也不能用标准 compute 路径匹配**，需要 enriched CSV（加 seqlen 相关列）+ 专属匹配逻辑。调用链：`torch_npu.atb.npu_ring_mla(seqlen=query_lens)` → `RingMlaAtb.cpp` → ATB `ring_mla_operation.cpp` → `RINGMLAPrefillTiling(totalTaskNum=sum(qSeqLen))`
4. **avg_seq_len 列缺失时的行为**：如果 CSV 没有 enriched 列（纯 profiling 数据），直接返回 MISS，不要 fallback 到 shape-only 匹配。FIA 和 RING kernel 均适用此规则

## 6. TCX 注意事项

1. **Enriched CSV 需要 2 个新增列**：`avg_seq_len`（INT，单位 token，microbench 时所有请求设相同 context length）+ `sparse_mode`（INT，0-4，vLLM decode 通常为 3=right_down causal）。sparse_mode 2/3 vs 0/1 差 ~50% 计算量，必须匹配
2. **扫描范围需和 ZH 对齐**：覆盖 Qwen3 (N=4, D=128) + DSV3 MLA (N=16, D=512) 两种 head 配置
3. **Profiling FIA 数据保留**：avg_seq_len 列填 -1 或者推测的结果，不删除数据行。用于 E4 验证：microbench 在相同 (Q shape, dtype) 下的预测值 vs profiling 实测值，误差 <20%
4. **RINGMLAPrefillBF16Kernel CSV**（T3）：和 FIA 同类问题，需要 enriched CSV。RING kernel 的 `seqlen` 参数含 per-request token 数（shape `[batch]` 或 `[2, batch]`，int32），microbench 时需控制 seqlen 值并记录到 CSV。`RINGMLAPrefillBF16Kernel_run.py` 当前因缺 seqlen 默认全量计算（2048 tokens → 243us），实测可能只算 128 tokens（→ 32us），导致 7.5 倍 gap
