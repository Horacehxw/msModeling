## Qwen3 DC 回退根因分析

### 现象
- Baseline: 63 ops total (56 hit, 7 miss)
- Merge: 56 ops total (48 hit, 8 miss)
- 少了 7 个 ops，其中 8 个原来 HIT 的变成了 MISS 或消失

### 根因
**develop 的 plugin 架构 (`transformations.py`) 产生了不同的 op graph**

develop 重构了模型转换流程:
- 之前: `TransformerModel` 内联 `patch_attention`, `patch_moe`, `shard_model` 等方法
- 之后: 独立函数在 `transformations.py` 中，通过 `custom_model_registry` dispatch

这个重构改变了 Qwen3 decode 模式下的算子图:
- 某些 view/permute 操作在新路径中被优化掉了 (op count 从 63 → 56)
- 同时部分之前 HIT 的 shape 现在因为新路径产生了不同的中间 shape

### MISS 详情 (merge)
| Op | Reason | TC Shape | 说明 |
|----|--------|----------|------|
| `aten.mul.Tensor` | elementwise_output_shape_mismatch | `(1,16,5120)` vs `(1,16,1)` | 新 shape |
| `tensor_cast.rms_norm` | shape_mismatch | `(1,1,5120)` vs CSV `(1,5120)` | batch dim 未 strip |
| `tensor_cast.apply_rope` | shape_mismatch | `(1,1,16,128)` | 新 shape |
| `tensor_cast.attention` | shape_mismatch | `(16,512)` | decode attention shape |
| `tensor_cast.add_rms_norm2` | shape_mismatch | `(1,1,5120)` vs `(1,5120)` | batch dim |
| `aten.add.Tensor` | elementwise_output_shape_mismatch | `(1,1,5120)` vs `(1,5120)` | batch dim |
| `tensor_cast.reshape_and_cache` | shape_mismatch | `(16,128)` | 新 shape |
| `aten.index.Tensor` | shape_mismatch | `(40960,256)` | 新 shape |

### 结论

**这不是 merge bug，而是 develop 架构重构的 side effect。**

接口设计遵从 develop (plugin 架构) 是正确的选择。Qwen3 DC 的 M3 回退从 57.1% → 38.5% 需要后续通过以下方式恢复:

1. **shape matching 增强**: `(1,1,D)` vs `(1,D)` 的 batch dim strip 在 decode 模式下需要处理 3D→2D 的情况
2. **补采 microbench**: 新产生的 shape 需要在 CSV 中覆盖
3. **op_mapping 更新**: 新路径产生的 op 可能需要新的 mapping entry

## DSv3 DC M5 轻微回退

M5 从 57.4% → 54.3% (-3.1pp)，在可接受范围边缘。原因类似 — develop 的转换路径变化导致部分大延迟 op 的 shape 变化。

## 解决方案

| 优先级 | 方案 | 影响 | 预期收益 |
|:------:|------|------|:-------:|
| P0 | 增强 `_strip_batch_dim` 处理 `(1,1,D)` → `(1,D)` 的 decode 3D shape | Qwen3 DC M3 | +10-15pp |
| P1 | 为新产生的 attention/rope shape 补采 microbench | Qwen3 DC M4 | +5-10pp |
| P2 | 检查 DSv3 DC 新路径的 shape 变化 | DSv3 DC M5 | +2-3pp |
