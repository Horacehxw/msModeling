## 一、执行摘要

Phase 1 于 3.15 通过 GO/NO-GO 评审。**Phase 2 进入第 2 天 (3.16–3.19)**，核心矛盾是: **M3 指标 (真实算子命中率) 仅 12.9%–43.8%，距 90% 验收标准差距巨大**。

本周聚焦三大 P0: (1) **DFC 融合 Pass** — 占 DSv3 35.3% 延迟，WYH 已提交初版 PR; (2) **FIA 微测格式** — ZZY 发现 TC 侧 FIA 解析缺失，正从 OpInvokeInfo 入手重建; (3) **通信建模** — HDY 发现 microbench vs profiling 存在 1.66x–20.6x gap，建模方案未定。

即使全部 P0+P1+插值完成，M3 预估天花板: Qwen3 75-85% / DSv3 65-75%，**仍低于 90% 验收线**。需要 SE 决策: 是否调整验收标准 or 扩大数据采集范围。

新成员张子哲 (ZZH) 今日入组，配对 TCX 做微测工具链。QCX 本周不在，异步沟通。

## 六、下一步建议 (按优先级)

### 1. 🔴 [SE 决策] 验收标准调整

**问题**: M3 天花板分析显示 Qwen3 75-85% / DSv3 65-75%，距 90% 有 5-25pp 差距。差距来源 (TC 主分支 SP/MLA 修复 + tier=0 数据 + 结构性不匹配) 在 3.23 前无法闭合。

**建议**: 区分 Phase 3 交付的"验收标准"为两档:
- **基线**: M3 > 60% (Qwen3) / M3 > 50% (DSv3) — 证明系统可用
- **目标**: M3 > 90% — 长期持续迭代

### 2. 🔴 [今日] 通信建模方案定论

HDY 提出用 profiling 数据 (compute + comm = E2E) 替代 HCCL microbench 建模。需 SE 审视:
- sync 模式: 通信延迟直接加到 layer 延迟
- async 模式 (prefill): 通信可能被计算 overlap，需分开建模
- 4 种 comm op 行为各异 (allReduce sync, allGather 有 rank-wait variance)

### 3. 🟡 [本周] DFC 端到端打通

WYH DFC fusion PR → ZZY/HDY DFC CSV → ZH composite 查询验证。这是 DSv3 M3 从 ~15% 到 ~35-45% 的关键路径。三人串行依赖，任何一环延迟都影响 Phase 3。

### 4. 🟡 [本周] FIA 微测路径重建

ZZY 发现 TC 侧 FIA 解析缺失，无法从 CANN 层精确匹配 shape。正在从 OpInvokeInfo 入手。影响 Qwen3 M3 +5-10pp。

### 5. 🟡 [持续] 微测 vs 整网 gap (R10) 修正因子

TCX 确认 MatMulV2 存在 NZ format + transpose + L2 cache hit 导致的单算子 vs 整网性能差异。需要建立修正因子方法论，否则微测数据替换 profiling 数据时精度下降。

### 6. 🟢 [低优] 同步 feat/perf-database 到 remote

本地 feat/perf-database 落后 gitcode/feat/perf-database 2 个 commit (748e226); gitcode-ascend/develop 有 10 个未合入 commit (含 "plugin-based custom model" 等新功能)。建议:
- Pull gitcode/feat/perf-database 的 2 个新 commit
- 评估上游 10 个 commit 的合入影响
