## 二、MISS Gap 全量根因分析

### 2.1 Gap 分类汇总

| 根因类别 | 影响 ops | 说明 | 解决方案 | 影响场景 |
|---------|:--------:|------|---------|---------|
| **缺乏融合 pass 建模** | 3 | DFC SinkSplit 不支持 gate+up 双 consumer → permute/all_to_all/unpermute 残留 | LJW 完全匹配 pass | DSv3 PF/DC |
| **缺乏 shape matching 规则** | 10-12 | FIA format, MLA/MLAPO composite, elementwise, KV cache, swiglu input_count | 代码修改 (~100行) | 全部 |

## 六、关键发现总结

### 6.1 DSv3 0319 通信模式变化
旧 0316: hcom_reduceScatter_ + allGather → 新 0319: **hcom_allReduce_ + allGather** (reduceScatter 消失)

### 6.2 DFC Fusion Pass 不触发根因
MoE Expert gate+up 双路 consumer → SinkSplitPass 模式不匹配 → grouped_matmul 不产生 → DispatchFFNCombinePass BFS 找不到 pattern

### 6.3 M6 指标可信度 (M6 = TC_prediction / real_per_fwd)

| 场景 | TC 预测 | Real per-fwd | M6 | 判断 |
|------|:------:|:-----------:|:--:|------|
| Qwen3 PF (+FC) | 5,545ms | 1,147ms | 4.83 | 过估 — reduce_scatter CSV 16x 膨胀 |
| Qwen3 DC | 12.5ms | 32.8ms | 0.38 | 低估 — 通信 op (无 FC) 覆盖不足 |
| DSv3 PF | 276ms | 295ms | 0.96 | ⚠️ "对的答案，错的原因" — HIT 高估 + MISS 低估相消 |
| DSv3 DC | 181ms | 51ms | 3.51 | 过估 — cudagraph 加速 + microbench 膨胀 |

R10 (microbench CSV 膨胀) 是 M6 有效性的前提。修复 MISS (如 DFC 匹配) 后 M6 会恶化而非改善。建议 Phase 3 验收以 M3+M5 为主指标，M6 仅作方向性参考。

### 6.4 FlashComm v1 效果
Qwen3 PF 加 --enable-flashcomm-v1 后: M3 33%→50%, M5 62%→88.5%。但 reduce_scatter CSV 有 16x 膨胀, 影响 M6。Decode 暂不启用 (cudagraph 路径可能不走 flashcomm)。
